---
title: Using TanStack Query
description: What SleekStack adds on top of TanStack Query.
---

SleekStack uses TanStack Query directly (ADR 0018 supersedes the native query layer of ADR 0014). Everything in the TanStack docs applies; this page lists what the bridge adds.

| TanStack Query | SleekStack |
| --- | --- |
| `new QueryClient()` + `QueryClientProvider` | `QueryClientLive()` in a `LayerProvider` + `QueryProvider` (client disposed with the scope) |
| `queryFn` (a Promise) | `effectFn(effect)`: an Effect whose Tags come from the client's layer |
| `prefetchQuery` + `dehydrate` | `prefetchQueries` from `@sleekstack/next` (runs on the configured runtime) |
| `HydrationBoundary`, hooks, devtools | used as is |
| `queryOptions` / `useMutation` without Effect | kit `cachedQuery` / `mutation` (generator bodies, `yield*` Tags) |
| hooks outside React | `useQuery` / `useMutation` from `@sleekstack/ui/query` |

## Differences from the old native layer

- Query errors are untyped: an Effect failure reaches TanStack as a rejection.
- Retry, staleness, garbage collection and refetch triggers follow TanStack's defaults and options.
- `sleekstack check` does not read `effectFn` bodies; a missing Tag rejects at run time.
