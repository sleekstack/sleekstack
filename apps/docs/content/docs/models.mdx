A record crosses the wire twice: once as what the read endpoint returns, once as what the write endpoint takes. This page is the contract for both directions: `ModelSpec`, `DraftSpec` and `useDraft` in `@sleekstack/model`, a package an app installs to opt in ([ADR 0038](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md), [ADR 0040](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0040-model-package.md)). The idea of a record and its editable copy comes from EmberData, through ramcinpay-front. [Records](#records) add what EmberData keeps around them: one shared record per type and id, relationships, and adapters that own the wire ([ADR 0041](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md)).

## The one idea

Read and write shapes are not inverses. The **Model** is the shape a component renders, and it holds labels (a country's name for its code, a formatted date) that the client cannot turn back into wire data. The write endpoint usually takes a different body from the one the read endpoint returns. So there is no `toDto(model)`: the two directions meet at the Model ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)).

<include>../../snippets/models/directions.txt</include>

- Read: `fromDto(dto, ctx)` builds the Model.
- Write: `create` seeds a **Draft**, an editable copy of the Model and one save boundary. `toDto` turns the Draft into the write body. A Model with two parts saved by two requests has two Draft Specs.
- Back: `toModel` projects an unsaved Draft into a read shape, for a live preview or an optimistic update.

`ModelSpec` and `DraftSpec` are types only, so Kit Operations, server code and tests use them through `import type`, which loads nothing at run time ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)). ## The read side

`ModelSpec<Dto, M, Ctx>` has one member, `fromDto(dto, ctx)` ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)).

- `fromDto` is pure: no clock, no locale, no random value, no read of anything outside its arguments. It runs whenever its inputs change, so an ambient read inside it would freeze at whatever it was when the data arrived.
- `ctx` is resolved data the DTO does not carry, such as country names by code. It is never a Service, a client or anything else with behaviour: if a Model needs to do something, the work belongs where the data is fetched. Declare `ctx` per Model (`{ countries }`), not as one shared bag.
- `Ctx` defaults to `void`, so a Model that needs nothing keeps a one-argument `fromDto`.
- A Model is always whole. When `ctx` comes from a second request, build the Model once both have landed and show the pending state until then, rather than a Model with codes in place of names.

Call `fromDto` where the data arrives. When the DTO and `ctx` are atoms, a derived atom binds them and recomputes when either changes. When they come from Services, `useDerivedAtom` runs the requests in the component's Effect and holds the Model in a `Result`:

## The write side

`DraftSpec<D, Dto, Src, P, E, R>` describes a Draft `D` seeded from a source `Src` ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)):

- `schema(src)` validates the Draft. It is an Effect Schema whose Type and Encoded are both `D`.
- `create(src)` is the seed: the Model's values for an edit form, blanks for a create form.
- `toDto(draft, src)` is the write body, as an `Effect<Dto, E, R>`. What it needs (ids, the clock) are Services in `R`, and its failures are `E`. A Form Action that yields `draft.toDto()` takes both, so `sleekstack check` reports them like any Handler's.
- `toModel(draft, src)` is optional: the Draft as a Model of type `P`. It must be total over a half-filled Draft.
- `diff(base, next)` is optional: a minimal PATCH body between two Drafts.

`schema`, `create`, `toModel` and `diff` are pure; only `toDto` reads ambients, because it runs once per submit. `Src` carries both the seed and anything else the spec needs, and is `void` when there is neither.

### Strings in, convert in `toDto`

A Draft field holds what its input holds, so a number input's field is a `string`. Validate the string in the schema and convert it in `toDto` ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)). A coercing schema such as `NumberFromString` is a type error: its Encoded is not its Type, and the field would no longer hold what the input shows ([ADR 0038, Rejected](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#rejected)). Bound what the schema accepts: `/^\d+$/` passes a 400-digit string that `Number` turns into `Infinity`.

## `useDraft` in depth

`useDraft(spec, src)` returns the Draft: atoms in the component's Store, the same Draft and the same `field(name)` atoms on every run ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)).

### The atoms

- `value` is the whole Draft, writable. `field(name)` is one field, writable, and returns the same atom for a name on every call. An atom placed in JSX, such as `value={draft.field('name')}`, binds the input without re-running the component.
- `errors` holds the schema's messages by field path: `'name'`, `'items.0.name'`, and `''` for the whole Draft. `valid` is true when there are none.
- `dirty` is true when the Draft differs from its seed by the schema's `Schema.equivalence`, not by reference. Editing a field back to the seed makes the Draft pristine again.
- `preview` is `toModel` of the Draft, and `changes` is `diff(seed, draft)`. `preview` is in the type only when the spec has `toModel`, and `changes` only when it has `diff`; for a union of specs, only when every member has the method ([ADR 0038, Consequences](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#consequences)).
- `errors`, `valid`, `dirty`, `preview` and `changes` are derived atoms, computed only when something reads them.
- `reset()` re-seeds from the current source; `dirty` is false after.
- `toDto()` decodes the Draft with the schema, then runs `spec.toDto` on the decoded Draft.

### The source

`src` is a value or an atom, and the Draft starts as `spec.create(src)` ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)).

- While the Draft is pristine, a new source re-seeds it: a refetch shows the new record. After an edit the edits are kept and `dirty` stays true, so a refetch never discards what the user typed. After a save, call `reset()` to seed from the saved record.
- A value `src` and the spec are compared by structure (plain objects and arrays, with functions by identity) or by `Equal`, so a literal or `{ ...Spec }` rebuilt on every run is not a change.
- Another spec on a later run re-seeds the Draft, including another instance of the same spec class.
- A spec with no source still takes the argument: `useDraft(Spec, undefined)`.

### Limits

These follow from ADR 0038's [Consequences](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#consequences):

- `field(name)` takes a plain record Draft's property names or an array Draft's indexes. A field write copies the Draft, so a getter of the record is copied as its current value.
- A primitive Draft, such as a string, has no fields: write `value`.
- A class instance (a `Date`, a `Map`, a `Schema.Class`) has no fields either. A copy would lose its private fields and internal slots, so write the whole instance through `value`. `field` throws a `TypeError` on one, and its type takes no name when the class has methods or private members.
- A class instance that is not `Equal`, as a source or a spec, is compared by identity. A new instance passed on every run re-seeds a pristine Draft on every run: pass an atom or a stable value.

<include>../../snippets/models/limits.tsx</include>

`useDraft` takes a slot like `useLocal`: call it at the top of the component, or `sleekstack check` reports `ConditionalSlot` (see [the slot rule](/docs/ui#the-slot-rule)). The Draft and its atoms are released with the instance. Outside a component it returns a new Draft without a slot, whose atoms live while something reads them.

## Who calls `toDto`

A Form Action does ([ADR 0038, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#decision)). In `EditProfile` above:

- The action yields `draft.toDto()`. A `ParseError` from the schema, or a failure of `spec.toDto`, stays in the `Result` of `useAction`; it is not sent to `onError`. See [Action state](/docs/forms#action-state).
- `useFormStatus(result)` gives `pending` while the save runs.
- The component never builds the write body itself: the spec does.

`toModel` is also the `apply` of `useOptimistic`: while the save runs, the saved Model shows the Draft applied, and when the save ends it shows the source again.

## Records

A Model built in a component is that component's copy: a save in one view does not reach another that shows the same server record. A **Record Type** fixes that. `defineRecord(type, { fields, adapter })` keeps one record per type and id in the Store's **Identity Map**, and every view, relationship and save reads and writes that one value ([ADR 0041](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md)). It has four parts, each with one job:

- The **Record Type** holds the fields as Effect Schema (with a string `id`), the per-field Transformations, the relationship fields and the adapter Tag.
- A **Transformation** is one field's wire format.
- The **Record Adapter** is the wire contract: response envelope, request body, PATCH shape. It is an app-written Service behind an app-declared Tag, supplied as a Layer.
- The **Draft** is derived from the record: input validation, `dirty`, `reset`, `errors`.

<include>../../snippets/models/records.ts</include>

### Fields and Transformations

A field is any Effect Schema. When the wire format of a field is not what the app holds, define a Transformation once and attach it to each field that uses it with `field(Money, { currency })` ([ADR 0041, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md#decision)):

- `from` is the wire value, `to` the app value. `to`'s Encoded is what the Draft's input holds, so bound it there (`Money` caps the digits before `serialize` runs `Number()`).
- `hydrate(wire, ast)` runs when wire data becomes a record; `serialize(input, ast)` when a Draft becomes a change. Both are Effects that fail with a `ParseIssue` such as `new ParseResult.Type(ast, value, message)`, surfaced as a typed `ParseError`.
- `defaultValue()` fills a field whose wire value is `undefined` and seeds a new record's Draft.
- A Transformation is passed as a value, never looked up by name, and reads its own field only. A value computed from several fields is a derived atom.
- Dates and numbers from strings need no Transformation: Effect Schema has them.

### The Identity Map

- `Book.push(wire)` decodes the wire (running each `hydrate`) and replaces the record of its id. A `ParseError` writes nothing. It needs the `Store` as a Service, because an Effect run outside a component has no Store of its own.
- `Book.atom(id)` is the record in the reading Store: `None` until it is pushed. It is the same atom for an id on every call.
- A record stays until the Store is disposed or `Book.evict(id)`, whether or not anything reads it. `evict` empties the slot and keeps its atom, so a later `push` fills the same atom.
- The map is client-only: no record atom is serialized for SSR. With `queryOf` below, it refills from the hydrated Query cache.

### Relationships

`ref(() => Author)` is a to-one field (wire `string | null`) and `refs(() => Author)` a to-many one (wire `string[]`). The target is a thunk, read only when the relationship is ([ADR 0041, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md#decision)).

- `Book.related(id, 'author')` is a derived atom: `None` while the book is not in the map, otherwise a `RecordRef { id, value }` (or `null`) for `ref`, a list of them for `refs`. It is the same atom for an id and field on every call.
- It follows the book and every target in the map, so a later `push` of the author updates it. It never fetches: load the author yourself (`Author.find`, or a list response pushed record by record).
- A missing target keeps its id and its position with a `None` value, and a list keeps the server's order.
- Relationships go one way. A reverse view built from `related` covers loaded records only.
- Two Record Types that refer to each other, or one that refers to itself, need one definition annotated with its type (`const Post: RecordDefinition<'post', PostFields> = defineRecord(...)`), as TypeScript cannot infer the cycle.

### Loading: `find` and `useRecord`

With an adapter, a Record Type has `find` and `commit`; without one, it has the rest. Neither needs `@sleekstack/query`.

- `Book.find(id)` calls the adapter's `find`, hydrates the wire and writes the record into the map. Its `R` holds `Store` and `BookApi`, so `sleekstack check` reports a missing adapter Layer, and its `E` holds the adapter's failures and `ParseError`. Concurrent calls for one id in a Store share one adapter call. The Store's scope owns the call: disposing it interrupts the call and writes nothing.
- `useRecord(Book, id)` is a slot hook that reads the map and runs `find` once while the map has no record. It returns a `Result`: `Initial` while waiting on the first load, `Success` with the map's value, or a `Failure` with the typed error. A record in the map is a `Success` whatever the fetch does, so a refetch keeps showing it.
- The adapter's Layer is where REST and GraphQL differ: `BookRest` above removes `{ data }`; a GraphQL Layer would remove its own envelope for the same Tag. A test supplies a fake Layer the same way.

### Saving: `commit` and the derived Draft

`Book.useDraft(id)` returns a Draft of the record: every field but `id`, in its input form (a date as its string, a `field(...)` as its `to` input), validated by the fields' Schemas ([ADR 0041, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md#decision)).

- It is seeded from the map, or from each field's `defaultValue` while the record is missing, which is the create form. There is no separate `create()`.
- The Draft and the record are two objects: an edit never touches the shared record.
- A pristine Draft re-seeds when the record changes. An edited one keeps its edits and measures `dirty` against the newest record, so after a save it is clean if it holds the saved value. Value A, submit B, edit to C, acknowledge B: B reads clean and A dirty.
- It takes a slot like `useDraft`. It exists only for fields whose Schemas need no Service, because a Draft seeds and validates synchronously.

`Book.commit(id, draft)` is pessimistic:

- It validates the Draft (a `ParseError` before any `serialize`), serializes it to a `RecordChange`, sends it with the adapter's `save`, and writes the hydrated response into the map. Nothing is written before the server acknowledges.
- A failure writes nothing and leaves the Draft as it is. A save that succeeded with a response that does not hydrate, or that is another record, fails with `SaveResponseError`.
- A second `commit` of the record while one is saving fails with `SaveInFlight`.
- A `find` response whose request started before the last acknowledged save is dropped, so a slow fetch never overwrites a save.
- `DraftSpec.toDto` is not involved: the wire body is the adapter's job. Standalone `useDraft(spec, src)` is unchanged.

### Caching: `@sleekstack/model/query`

`find` de-dupes only calls in flight; it does not cache. For caching and stale handling, the optional entry `@sleekstack/model/query` exports `queryOf(record)`, which runs the same steps through the Query Client ([ADR 0041, Decision](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md#decision)). It is the only entry that needs `@sleekstack/query`, an optional peer; the base entry never loads it.

<include>../../snippets/models/book-query.tsx</include>

- `queryOf(Book).query(id)` reads the entry `['book', id]`, fetching with the adapter's `find` when it is missing or stale. Every read writes the record into the map, a cache hit and a hydrated entry included.
- `useRecord(Book, id, { via: queryOf(Book) })` fetches through the Query Client, with the same `Result` states as the default.
- The query function runs with the services of the Query Client Layer, not of the component: give that Layer the app's Store and the adapter Layer, or the read fails with a defect naming the missing Tag.
- An entry is written into the map only when it is newer than the record's last acknowledged save, so an older cached entry never overwrites a save. After a commit, the saved record is written into the entry.

### Checklist for a new Record Type

1. Write the fields as Effect Schema with a string `id`, bounded where an input feeds them. Add a Transformation only for a wire format Effect Schema does not cover.
2. Declare the adapter Tag once at module level, with the wire type, the change type and the failure type, and write its Layer: remove the envelope in `find`, shape the body in `save`.
3. Add `ref` and `refs` fields for relationships, and load their targets where the data arrives.
4. Read with `useRecord`, edit with `record.useDraft(id)`, and save with `record.commit(id, draft)` in a Form Action.
5. Provide the Store and the adapter Layer to the app's Layer, and to the Query Client Layer when using `queryOf`.
6. Test with a fake adapter Layer.

## Checklist for a new Model and Draft

1. Type the read DTO, the write body and the Model. Put the Model and its Draft Specs in one file that imports no UI.
2. Write `fromDto`. Anything it needs that the DTO does not carry goes in a narrow `Ctx` of resolved data.
3. Type the Draft as its inputs hold it (strings for number and date inputs) and write a schema whose Type and Encoded are that Draft, with bounded checks.
4. Write `create`, then `toDto` as an Effect: ambients are Services in `R`, failures are `E`, conversion from strings happens here.
5. Add `toModel` for a preview or an optimistic update, and `diff` for a PATCH endpoint, only when a component uses them.
6. Bind `ctx` where the data arrives: a derived atom or `useDerivedAtom`.
7. Call `useDraft(spec, src)` at the top of the component, bind inputs to `field(name)`, and yield `draft.toDto()` in the Form Action.
8. Write the spec tests and one component test.

## Common mistakes

- **A `toDto(model)`, or one Schema transform between Model and DTO.** The read Model and the write body are different shapes ([ADR 0038, Rejected](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#rejected)).
- **A Service or a client in `ctx`.** `ctx` is data. Fetch with Services where the data arrives, then pass what came back.
- **A clock or locale read in `fromDto`, `create` or `toModel`.** They are pure; move the read into `toDto` as a Service, or into the component.
- **A plain `toDto` function.** It hides its ambients from `R` and from the Analyzer; it is an Effect ([ADR 0038, Rejected](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#rejected)).
- **`NumberFromString` in the Draft schema, or an unbounded digit check.** The first is a type error; the second turns a long string into `Infinity`.
- **Re-seeding by hand when the source changes.** `useDraft` re-seeds a pristine Draft and keeps edits; a hand-written reset on every new source discards what the user typed.
- **A new class instance as `src` on every run.** It re-seeds a pristine Draft on every run. Pass an atom or a stable value.
- **`useDraft`, `useRecord` or `record.useDraft` inside a condition.** Each takes a slot: `ConditionalSlot`.
- **Editing the record in the map.** Edit its Draft and `commit`; the map holds what the server acknowledged.
- **Expecting `related` to fetch.** It reads the map; load the targets where the data arrives.

## Not covered

ADR 0038 leaves these to user code ([Rejected](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0038-model-and-draft.md#rejected)):

- Filters: a URL-to-query round trip has no save boundary and no validation, so it wants its own contract.
- Exported `fromDto`/`toDto` helpers, coercion helpers and `<input bind>` sugar.

Records leave these out of v1 ([ADR 0041, Consequences](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0041-records-layer.md#consequences)):

- Inverse sync between relationship sides, optimistic writes to the shared record, partial records and unknown relationship membership, pagination and polymorphism.
- An HTTP client or a JSON:API format: the Record Adapter is app code.
