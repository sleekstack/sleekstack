`@sleekstack/next` holds one Effect runtime per process and runs Effects on it (`runEffect`); the action/query sugar (`defineEffect`, `effect`, `defineQuery`, `query`) lives in `@sleekstack/kit/next`, which is built on `runEffect`. A request scope is opened for every call. Request-lifetime services are built in that scope and cleaned up when the call ends, so no state leaks between requests.

## Runtime

Call `configureRuntime({ layer, onError })` once at module load, for example from `instrumentation.ts` or a shared server file. `layer` is a plain Effect Layer; kit passes `{ provide }` (modules and entries) instead. The same config object, or one with the same `id` (so the RSC and Server Action bundles, which each load your module, agree on one runtime), is a no-op; pass `{ replace: true }` as the second argument to replace it anyway (a dev hot reload of the configuring module). A different one interrupts in-flight calls, then disposes the old runtime and replaces it. The runtime builds lazily on the first call; a failed build is not cached, so the next call retries. A call before `configureRuntime` rejects with `RuntimeNotConfigured`.

`onError` receives defects (once each) and finalizer failures; with the module-based `{ provide }` config (kit) `onFinalizerError` takes the finalizer failures instead. A sink that throws is swallowed and never changes the call's result; `redirect()`/`notFound()` (also when thrown inside a kit handler) and interruptions pass through unreported. In kit `onFinalizerError` gets a plain `FinalizerError` (`{ message, tag }`); in `@sleekstack/next` it gets the Effect `Cause`.

## Actions and queries (kit)

The functions `defineEffect` and `defineQuery` return are plain async functions. To call one from a Client Component, export an async wrapper from a `'use server'` file, as below.

`defineEffect(function* (...args) { ... }, opts?)` declares a generator that `yield*`s the Tags it needs and returns a function; each call runs it, resolving each yielded Tag from the request scope on demand. `effect(gen, opts?)` is the same run, immediately, for a generator written inline. An effect resolves `{ ok: true, data }`, or `{ ok: false, error }` after `fail(message)`. `defineQuery`/`query` are the same for reads: they resolve the plain value, and `fail` rejects. Pass `{ provide }` as the last argument to build extra Layers in that call's request scope, shadowing the runtime graph, and `{ scope: [Tags] }` to build Tags the body never yields (e.g. a request-scoped `RequestContext` that only logs).

## Running Effects (Effect)

`runEffect(effect, { request?, overrides? })` runs an Effect on the configured runtime and rejects exactly as `Effect.runPromise` does. `request` is a Layer built per call and released when the call ends; `overrides` is provided outside it, so it shadows both the Effect's and `request`'s services for that call only. Wrap calls in `'use server'` functions to use them from Client Components.

## Devtools

In development `@sleekstack/next` records request scopes, the app runtime's acquire/release and reported errors in a bounded (200 events) per-process buffer, and `@sleekstack/next/devtools` exposes it, with the analyzer report, through a route handler (404 in production). `@sleekstack/devtools` renders it as a panel; mount it only outside production so client bundles never include it.

## Migrating from `action`/`query` in `@sleekstack/next`

`action`, `query`, `Operation` and `OperationOptions` were removed from `@sleekstack/next` (ADR 0012). Use kit's `defineEffect`/`effect`/`defineQuery`/`query` from `@sleekstack/kit/next`, or call `runEffect` with your own Effect and Layer.
