---
title: Next.js
description: Server Actions and queries that run in a request scope.
---

The Next.js adapter holds one app runtime per process and opens a request scope for every `action` or `query` call. Request-lifetime services are built in that scope and cleaned up when the call ends, so no state leaks between requests.

## Runtime

Call `configureRuntime` once at module load, for example from `instrumentation.ts` or a shared server file. The same config object again is a no-op (safe under HMR); a different one disposes the old runtime and replaces it. The app scope builds lazily on the first call. A call before `configureRuntime` rejects.

`onFinalizerError` receives cleanup failures. In kit it gets a plain `FinalizerError` (`{ message, tag }`); in `@sleekstack/next` it gets the Effect `Cause`.

## Actions and queries (kit)

The functions `defineEffect` and `defineQuery` return are plain async functions. To call one from a Client Component, export an async wrapper from a `'use server'` file, as below.

`defineEffect(function* (...args) { ... }, [Tags], opts?)` declares a generator that `yield*`s the Tags it needs and returns a function; each call resolves those `deps` from the request scope and runs it. `effect(gen, deps, opts?)` is the same run, immediately, for a generator written inline. An effect resolves `{ ok: true, data }`, or `{ ok: false, error }` after `fail(message)`. `defineQuery`/`query` are the same for reads: they resolve the plain value, and `fail` rejects. Pass `{ provide }` as the last argument to build extra Layers in that call's request scope, shadowing the runtime graph.

## Actions and queries (Effect)

In `@sleekstack/next`, an operation is a function returning an Effect that reads services with `yield*`. It resolves the Effect's value; a failure or defect rejects with an `Error` whose `cause` is the Effect `Cause`. Returning a `ReadableStream` or async iterable is not supported and rejects the same way, with a `StreamingResultNotSupported` failure inside the cause.
