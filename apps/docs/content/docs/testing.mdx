Two techniques cover most tests:

- **Validate the graph.** `sleekstack check` runs every graph check (missing providers, cycles, lifetimes, privacy) without running the app; run it in CI before the tests.
- **Swap a service with Shadowing.** A per-call `provide` builds Layers in the request scope and shadows earlier entries for that call only. In React, a nested `LayerProvider` with a test Layer does the same for a subtree. Neither needs a mocking API.

## `sleekstack check`

`sleekstack check [--project <tsconfig>] [--entry <file>...] [--json] [--lenient]` reads the project through the TypeScript checker; it never imports or runs your code. Every `configureRuntime` call outside test files is an app root, and every `request` or `overrides` Layer of a `runEffect` call is a request or overrides root, checked against its own provides plus the app root's; each is validated as its own graph and reported with its `kind`. `--entry` (repeatable, or `"sleekstack": { "entry": [...] }` in package.json) limits the roots to those files; a `configureRuntime` call in another file is then not checked. It exits 0 when clean, 1 on violations (each with file:line) and 2 on a crash or when no root is found. `--json` writes only JSON to stdout: each root's graph and errors.

A declaration the analyzer cannot read (`any`, a widened `Layer<any>[]`, a non-literal Tag key) is an error, not a skip. Loops, conditionals and computed lists are fine when their types are precise; they are over-approximated. `--lenient` turns an unresolvable `runEffect` Layer into an opaque root (exit 0) instead; an unresolvable app Layer and a missing Tag still fail. Run it as a `prebuild` script and as a CI step before the tests (ADR 0010).

When the project's package.json lists `@sleekstack/ui` (in any dependency field), `sleekstack check` also runs the component pass: each `mount` call is a root, and `MissingDependency`, `UnhandledError`, `EffectInsideReact`, `Unresolved`, `NonResumableHandler`, `ConditionalSlot` and `MissingKey` are reported with file:line (see [Errors](/docs/errors)). `--json` then adds a `components` key. Projects without `@sleekstack/ui` are checked exactly as before.

The Next.js runtime is one slot per process, so configure it once in a setup file and keep tests that need an unconfigured runtime first in their file.
