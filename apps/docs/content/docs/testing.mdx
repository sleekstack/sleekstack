Two techniques cover most tests:

- **Validate the graph.** `sleekstack check` runs every graph check (missing providers, cycles, lifetimes, privacy) without running the app; run it in CI before the tests.
- **Swap a service with Shadowing.** A request or `overrides` Layer passed to `runEffect` shadows earlier entries for that call only. In a ui tree, a nested `Provider` with a test Layer does the same for a subtree. Neither needs a mocking API. For a server function, a Server Service method or a route handler, `callServerFn`, `callService` and `callHandler` from `@sleekstack/testing` run it through `start(...).fetch` with a test layer and no network ([ADR 0039](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0039-start-server-core.md)). `callController` answers a request through a [Controller](/docs/controllers#testing)'s HTTP face the same way. In an app whose Vitest config has the `serverServices()` plugin, `start` also tries the discovered Controllers before the entry given to `callController`, so a discovered one that matches the same URL answers instead. `callService` takes a generated entry the same way as a hand-written one: pick it from `virtual:sleek/server-registry` (`services.find((s) => s.tag === Tally)`) and pass a `layer` that provides its Tag, or the services its generated implementation needs. With the plugin, the discovered app's Layer Files are still built under that `layer`, which wins for every Tag it provides but does not stop those builds: each call builds realworld's `DbLive`, for example. A defect comes back as the `Exit`'s cause and never reaches the Server Root's `onError`, and the entry is registered once beside the discovered one.

## `sleekstack check`

`sleekstack check [--project <tsconfig>] [--entry <file>...] [--json] [--lenient]` reads the project through the TypeScript checker; it never imports or runs your code. Every `configureRuntime` call outside test files (a file under `__tests__/`, `test/` or `tests/`, or named `*.test.*` or `*.spec.*`) is an app root, and every `request` or `overrides` Layer of a `runEffect` call is a request or overrides root, checked against its own provides plus the app root's; each is validated as its own graph and reported with its `kind`. `--entry` (repeatable, or `"sleekstack": { "entry": [...] }` in package.json) limits the roots to those files; a `configureRuntime` call in another file is then not checked. It exits 0 when clean, 1 on violations (each with file:line) and 2 on a crash or when no root is found. `--json` writes only JSON to stdout: each root's graph and errors.

A declaration the analyzer cannot read (`any`, a widened `Layer<any>[]`, a non-literal Tag key) is an error, not a skip. Loops, conditionals and computed lists are fine when their types are precise; they are over-approximated. `--lenient` turns an unresolvable `runEffect` Layer into an opaque root (exit 0) instead; an unresolvable app Layer and a missing Tag still fail. Run it as a `prebuild` script and as a CI step before the tests (ADR 0010).

When the project's package.json lists `@sleekstack/ui` (in any dependency field), `sleekstack check` also runs the component pass: each `mount` call is a root, and `MissingDependency`, `UnhandledError`, `EffectInsideReact`, `Unresolved`, `NonResumableHandler`, `ConditionalSlot` and `MissingKey` are reported with file:line (see [Errors](/docs/errors)). `--json` then adds a `components` key. Projects without `@sleekstack/ui` are checked exactly as before. In every project, each Controller under `server/routes` is a root too, so a server-only app is checked ([Controller errors](/docs/errors#controller-errors)).

The runtime is one slot per process, so configure it once in a setup file and keep tests that need an unconfigured runtime first in their file.

## Component tests

`@sleekstack/testing` renders a host component from `@sleekstack/ui` under Vitest with jsdom. `render(app, { layer })` mounts it inside React's act environment into a container attached to `document.body`, and disposes it after each test (or call `dispose()` yourself). `flush()` waits until the renderer has no work in flight: re-runs, post-commit effects, `Pending` content and handler fibers, including any `Effect.sleep` they wait on. It ticks every 10 ms and rejects with `FlushTimeout` after 100 ticks while work is still running, such as an effect that never ends (`flush({ tickMs, maxRounds })` tunes this). Work outside the renderer, such as a raw `setTimeout` or an unforked promise, is not tracked; use Testing Library's `findBy*` or `waitFor` for it. `mockLayer(Tag, impl)` provides a service from a partial implementation; calling a method you left out is a defect that names it. Queries come from Testing Library: install `@testing-library/dom` and `@testing-library/user-event` in your app and use them on the container.
