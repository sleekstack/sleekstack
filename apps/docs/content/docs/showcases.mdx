[`apps/showcase`](https://github.com/sleekstack/sleekstack/tree/master/apps/showcase) is a team task board built with `@sleekstack/ui` components on Effect Layers (see the [UI components guide](/docs/ui)). It is a Vite app: run it with `pnpm --filter showcase dev`.

The page mounts the app twice, as Ada (an editor) and Grace (a viewer). Each mount has its own atom store, and a `Provider` scopes the Viewer for everything under it. The code has one folder per domain under `src/modules/` (`identity`, `projects`, `tasks`).

The app links one page per feature, each opened in a `startTransition`:

- **Board and forms**: tasks read and written through `@sleekstack/query`, a new-task [form](/docs/forms) with `useAction`, `useFormStatus` and `useOptimistic`, a `Boundary` fallback for an unknown project, and a tab title that follows the open project through an effect.
- **Typed DOM** ([guide](/docs/typed-dom)): host elements typed per tag, atoms bound to attributes, `useRef`.
- **lazy** ([guide](/docs/lazy)): a chart in its own chunk under `Pending`.
- **Transitions** ([guide](/docs/transitions)): `startTransition` and `useDeferredAtom`.
- **Portal** ([guide](/docs/portal-boundary#portal)): a dialog in `document.body` that reads the Viewer of where it is rendered.
- **Boundary reset** ([guide](/docs/portal-boundary#boundary-reset)): a failed read whose fallback's `reset` re-runs the boundary's children.
- **Model and Draft** ([guide](/docs/models)): a Model built with `fromDto`, an edit Draft from `useDraft` with per-field errors, `dirty`, `reset` and a live `preview`, saved by a Form Action.
- **Router** ([guide](/docs/routing)): a `@sleekstack/router` app run by `startRouter` in the page, with a route table, a loader with a schema and `Link`s that prefetch it.
- **Devtools**: links the [devtools panel](/docs/ui-devtools), which opens below the demo in development only.

The app's [README](https://github.com/sleekstack/sleekstack/blob/master/apps/showcase/README.md) lists the source and test of each page.

Its tests cover server rendering, streaming, hydration and resume, the folder layering, the size budget of ADR 0022, and one fixture per error code of the Analyzer's component pass (`apps/showcase/fixtures/`). Some of them are written with [`@sleekstack/testing`](/docs/testing).

## Conduit (RealWorld)

[`apps/realworld`](https://github.com/sleekstack/sleekstack/tree/master/apps/realworld) is a [RealWorld](https://github.com/realworld-apps/realworld) ("Conduit") app: sign up, settings, feeds, tags, profiles, follows, favorites, articles with a markdown body, and comments. It is a full-stack app on one `node:sqlite` database. Run it with `pnpm --filter realworld dev`.

- **Pages**: file routes under `src/routes` (ui-vite's `routes()` plugin), with a root layout, a `(guarded)` layout and a `_notFound` page. The route files are the table: `tag/[tag].tsx` is `/tag/:tag`, and the pages that need a signed-in user sit in the `(guarded)` group. Loaders see only the pathname, so the feed tab and the tag are routes, and the page number is a client atom.
- **Server**: `@sleekstack/start` server functions serve the UI and authenticate with an `HttpOnly` session cookie. Page loaders call them in place while the server renders, so the signed-in header renders the same on the server and in the browser.
- **REST**: an `/api` facade follows the RealWorld API over the same services. The app's [README](https://github.com/sleekstack/sleekstack/blob/master/apps/realworld/README.md) has its status codes and the Postman run.
- **Forms**: login, settings, the editor and comments use a Draft from `useDraft` and a Form Action from `useAction`.
- **Markdown**: an article body is parsed by a small in-app renderer into ui nodes. ui has no raw-HTML node, so HTML in a body shows as text, and a `javascript:` link loses its link.

Its tests run the pages in a browser against the real server, server render and hydrate included, and check the folder layering and that the client chunk holds no server module.
