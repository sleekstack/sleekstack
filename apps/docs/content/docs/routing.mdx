`@sleekstack/router` is a separate package for apps on the `@sleekstack/ui` host (ADR 0036). A route table is a `const` object of path strings, and params are typed from those strings with no code generation. With the [Vite plugin](/docs/vite), the whole router can come from route files: `router({ table, pages, notFound })` from `virtual:sleekstack/routes`, with `[[page]]` and `[...slug]` file segments for optional and splat params, `_layout` files and lazy pages.

- A path segment `:name` is a param matching one non-empty segment. As the last segment, `:name?` is optional (`/u/:id?` matches `/u` and `/u/7`; `id` is absent when missing) and `*name` is a splat (`/files/*path` matches `/files/a/b` with `path` `'a/b'`, each segment decoded, and not `/files`). Either one elsewhere never matches. The first matching route in table order wins.
- `loader(key, schema, effect)` declares a loader. A page reads it with `useLoader`; the router wraps the page in `Pending` with the page's optional `fallback`, so no manual `Pending` is needed. A typed error reaches the nearest `Boundary`.
- `redirect(to)` and `notFound()` in a loader or action are control flow. `handle` answers 302 or 404; in the browser the router navigates or shows the not-found page. More than 10 redirects in a row fail with `RedirectLoop`.
- `handle` runs a page's declared loaders before a string render, so the response has the right status. With `stream: true` the shell goes out once they settle; loaders the page reads without declaring them stream under `Pending`, and their redirect or not-found is sent as a script. A loader error with a numeric `status` sets it; any other is a 500. The results reach the client through `Transfer`, so it does not load them again.
- `startRouter` handles same-origin link clicks, back and forward, and scroll restoration. A newer navigation interrupts the pending one and stops its loads.
- `Link` prefetches a route's code and loaders on hover or focus; `prefetch={false}` opts out. It passes other anchor attributes (`class`, `aria-*`, `data-*`, `rel`, `target`, ...) to the `<a>` and takes no event handlers; a `target` or `download` link still prefetches, as a warm-up only. `action(run)` takes any form a form `action` takes.
- A page can be `{ load: () => import('./page') }`, a module exporting its `render`, `loaders` and `fallback`. The router loads it once, before its loaders run or it renders, and before hydrating the first page; concurrent navigations share the load. A failed load renders a `LazyLoadError` at the nearest `Boundary`, and the next navigation tries again. Pass `code={pages.user.load}` to `Link` to prefetch it.
