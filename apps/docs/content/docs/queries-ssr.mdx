Prefetch on the server with `prefetchQueries`, then hand TanStack's dehydrated state to `HydrationBoundary`. The client's first render reads that data and does not fetch again until it is stale.

## The parts

- `prefetchQueries(queries, options?)` is in `@sleekstack/next`. It runs through `runEffect` (options: `request` and `overrides` Layers, as for `runEffect`), prefetches each `queryOptions` on the scope's `QueryClient` and returns `dehydrate(client)`. The run must provide `QueryClientTag`, usually by merging `QueryClientLive()` into `request`, so every request gets a fresh client.
- `HydrationBoundary` is TanStack's, from `@tanstack/react-query`. It needs a `QueryProvider` (or any `QueryClientProvider`) above it.
- An `effectFn` query prefetched this way sees the request scope's services, including `request` and `overrides`.

## Queries that were not prefetched

TanStack does not fetch during a server render: an un-prefetched `useQuery` renders `pending` on the server and fetches on the client. **Prefetch anything the first paint needs.**

## Mutations in a server render

TanStack's `useMutation` is idle on the server. `@sleekstack/ui`'s `useMutation` is also idle under `renderToString`, and its `useQuery` renders cached data without fetching. Its `renderToString` writes the query cache into the `data-sleek-hydrate` script and `hydrateMount` seeds the client QueryClient from it; a query skips the refetch on hydrate only when its `staleTime` is above 0.
