title: Queries on the server
description: Render queries on the server and hydrate them on the client.
---

`renderToString` and `renderToStream` from `@sleekstack/ui` write the query cache into the page, and `hydrateMount` seeds the client's `QueryClient` from it. The client's first render reads that data and does not fetch again until it is stale.

## The parts

- `UiQueryClientLive()` is `QueryClientLive()` plus the `Transfer` that carries the cache. A layer without it renders and hydrates without query state.
- `useSuspenseQuery` waits on the query inside `<Pending fallback>`; under `renderToString` it fetches and is awaited, with no fallback and no timeout.
- An `effectFn` query sees the services of the layer that built the client.
- A query skips the refetch on hydrate only when its `staleTime` is above 0.

## Queries that were not fetched

Under `renderToString`, `useQuery` does not subscribe or fetch: a query already in the cache renders its data, any other renders `pending` and fetches on the client. **Use `useSuspenseQuery` for anything the first paint needs.**

## Mutations in a server render

`useMutation` is idle under `renderToString`.

## From a server function

Server-side reads and writes that must not run in the browser belong in a server function of `@sleekstack/start`, which runs in the Request Scope of one request ([ADR 0039](https://github.com/sleekstack/sleekstack/blob/master/docs/adr/0039-start-server-core.md)). Call it from a query's `queryFn` through its client stub.
