SleekStack's queries are [TanStack Query](https://tanstack.com/query). `@sleekstack/query` is a thin bridge: a `QueryClient` that lives in a Layer's scope, and `effectFn`, which turns an Effect into a `queryFn` / `mutationFn`. Keys, caching, retries, optimistic updates and devtools are TanStack's own. See [Using TanStack Query](/docs/tanstack-query) for what the bridge adds.

## Effect queries

Provide `UiQueryClientLive()` in the mount's layer, over the layers your queries need, and read with `useQuery` and `useMutation` from `@sleekstack/query/ui`. `effectFn(effect)` turns an Effect into the `queryFn` / `mutationFn`.

<include>../../snippets/queries-effect.tsx</include>

- `QueryClientLive(config?)` is a scoped Layer providing `QueryClientTag`. Each mount layer that provides it gets its own client; the client is unmounted and cleared when that scope closes.
- `effectFn(effect)` runs the Effect with the services of the layer that built the calling client, so build the client over the layers its queries use. It rejects with the original failure or defect, and an aborted `signal` interrupts the fiber. Its `R` is not checked against the layer: a missing Tag rejects at run time.
- Query errors are not typed: TanStack sees a rejected Promise, so `error` is `Error` (or whatever the Effect failed with), not your `E`. This is a deliberate trade for TanStack's ecosystem.

## The ui hooks

`useQuery` and `useMutation` from `@sleekstack/query/ui` read the `QueryClientTag` of the mount layer. `UiQueryClientLive()` is `QueryClientLive()` plus the `Transfer` that carries the cache through `renderToString` / `renderToStream` and `hydrateMount`; a layer without it renders and hydrates without query state.

<include>../../snippets/queries-ui.tsx</include>

- `useQuery` shares one `QueryObserver` per key across components (ref-counted) and re-runs the component when its result changes.
- `useMutation` keeps one `MutationObserver` per component instance. `mutate` swallows the rejection (the error is in the result); `mutateAsync` rejects with the original error.
- `useSuspenseQuery` waits on the query inside `<Pending fallback>` and returns its data. It fails with the tagged `QueryFailed { cause }` (catch it with `<Boundary tag={QueryFailed}>`), shares the observer with `useQuery`, re-runs when the result changes and returns held data without refetching. A re-run keeps the previous content on screen; under `renderToString` it fetches and is awaited, with no fallback and no timeout.
- Under `renderToString` `useQuery` and `useMutation` do not subscribe or fetch: a prefetched query renders its data, any other renders `pending`, and `useMutation` is idle.

## Build-time checks

A `@sleekstack/ui` component using the query hooks requires `QueryClientTag` from its mount layer, and `sleekstack check` reports it as a `MissingDependency` when no layer provides it. An `effectFn` body is not checked.

## Devtools

The `@sleekstack/devtools` Queries tab reads the scope client's `QueryCache`.

## Limits

- Effect-typed query errors are gone: `error` is untyped (`useSuspenseQuery` wraps it in `QueryFailed`).
- An optimistic write is only a value in the cache. An item it adds (for example a new task with a temporary id) is not on the server until the refetch replaces it, so do not let users select such an item.
- Server rendering with prefetch is in [Queries on the server](/docs/queries-ssr).
