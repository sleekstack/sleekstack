# One public name, one meaning: the kit/next inline runner is `runOperation`

`@sleekstack/kit` exported `effect(fn, deps?, opts?)`, a side-effect Layer, while `@sleekstack/kit/next` exported `effect(gen, opts?)`, which runs a Kit Operation inline. The same name with two meanings made readers, and agents writing code, guess which one a file meant from its import path. The `kit/next` inline runner is renamed `runOperation`; kit's side-effect `effect()` keeps its name, because it is the older and wider-used one and lives on the main entry point. `effect` stays exported from `@sleekstack/kit/next` as a `@deprecated` alias of `runOperation` for one release, then is removed. The analyzer recognizes `kit/next/action#runOperation`, and still `kit/next/action#effect`, so `sleekstack check` keeps analyzing older code. The alias resolves to the same declaration as `runOperation`. A kit test fails when two entry points export one name with different declarations, with deprecated aliases listed explicitly.

Rejected: renaming kit's side-effect `effect()` instead. It is the main-entry API and appears as `effect:<name>` in the analyzer graph, so renaming it would change graph ids users already see.
