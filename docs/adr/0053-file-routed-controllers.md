# 0053. File-routed Controllers: REST on the Request Scope, typed by their signature

## Status

Proposed (draft). Amends ADR 0039 (route handlers at exact pathnames only; the request services gain `ResponseStatus`) and reuses ADR 0050's path syntax. Replaces the term Server Endpoint. Its wiring half is ADR 0054. Spec: fn-68.

## Context

ADR 0039's `start({ handlers })` serves a handler at an exact pathname and has no params (its listed known gap). Realworld works around that with `server/rest.ts`: one middleware over `/api/` with a 19-entry regex table that also resolves the viewer from `Authorization`, decodes each body and maps tagged errors to statuses. A handler is `(Request) => Effect<Response>`, so nothing types its input or output: each handler decodes by hand and nothing can generate a client from it.

ADR 0050 already turns files into routes for pages, and the Start proposal (`docs/proposals/start-framework.md`, section 4) planned `api/health.ts` as a route handler. Nothing built it.

## Decision

- **A Controller is a `*.controller.ts` file under `server/routes`** (plugin options `serverDir`, default `server`, and `controllersDir`, default `<serverDir>/routes`). Its path sets its URL with ADR 0050's syntax and match order: `[id]`, `[[id]]`, `[...rest]`, `(group)`, `index`, and `_` files are not routes. A segment with a malformed percent-escape matches only a param or splat position, and its value then fails to decode with `InvalidPathEncoding`; the page matcher matches no route instead. Two Controllers whose paths differ only in param names, and a Controller and a page at the same path, fail the build naming both files. A `start({ handlers })` entry at an exact pathname still wins over a Controller; a Controller wins over the page router. The prefix `/_sleek/` stays reserved.
- **A Controller Method is a named export** `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE` or `OPTIONS`. It is a function of one input object, `{ params?, query?, body? }`, returning `Effect<A, E, R>`. There is no wrapper function: the written-out signature is the declaration. `R` may be any service; the found Layers provide it (ADR 0054).
- **The annotation is the link to the Schema.** Before the method runs, the framework decodes `params` from the path, `query` from the URL and `body` from JSON. The analyzer reads the written-out type of each. `Schema.Schema.Type<typeof X>`, written inline or through a type alias in the same file, where `X` is an exported Schema value of a client-safe module, uses `X` itself. Any other type is printed to a Schema from ADR 0051's subset. Path and query values are strings, so a printed `number` or `boolean` gets a string codec; a referenced Schema is used as written. A form the analyzer cannot read is `ControllerMethodShape`. The keys of `params` must equal the path's params (`ControllerParamsMismatch`).
- **A value answers as JSON.** When the success type is written out, the value is encoded through its Schema, so fields outside it are not sent. Without a written success type it is serialized as it is. `void` is 204. The statuses 204, 205 and 304 carry no body: a value returned with one of them is not sent. A method with no written success type may return a `Response`, which passes through untouched.
- **The status and headers are request services.** `ResponseStatus` joins `Request`, `Cookies` and `ResponseHeaders`: `yield* ResponseStatus.set(201)`. The default is 200, or 204 for `void`. A value that is not an integer from 200 to 599 is a defect (`InvalidStatus`, a programmer error, so `E` stays clean). The status is read only by the Controller HTTP face. A method that sets a status and then fails answers with the status `wrap` gives the failure.
- **A failure reaches `wrap`.** A decode failure is a `ParseError` in the Effect `wrap` receives; without a `wrap` that handles it, it answers 400 with ADR 0039's `DecodeError` JSON. A malformed path escape is `InvalidPathEncoding` (unhandled: 404 with no body), and a method the path does not have is `MethodNotAllowed` carrying the allowed methods (unhandled: 405 with `Allow`). A body over the limit is `BodyTooLarge` (unhandled: 413), and a method that declares `body` requires `Content-Type: application/json`, else `UnsupportedMediaType` (unhandled: 415), which closes cross-site form posts to cookie-authenticated Controllers without an origin check. `wrap` can map all of them, which realworld needs to keep its JSON bodies for the 404, 413 and malformed-JSON answers. Any other unhandled failure is a defect: the error sink and an empty 500, as in ADR 0039. The body shape of an error answer belongs to the app.
- **`wrap` and Directory Defaults.** An option export `wrap` has the signature `(next, request) => Effect`, where `next` is decode, method and encode for the HTTP face. It provides services such as the viewer and maps failures to responses. A `_defaults.ts` file in a directory under `server/` takes the option exports `wrap`, `bodyLimit` and `origins`. Its `wrap` applies to every Controller below it and to nothing else: it is `Response`-typed, and RPC Files and the RPC Manifest take their own type-preserving `RpcWrap` (ADR 0054). `wrap` composes outer first, as ADR 0050 composes layouts. `bodyLimit` (bytes, a positive finite integer, default 1 MiB) resolves by specificity: the file's own export, the nearest `_defaults.ts`, `start({ bodyLimit })`, then the default, and it reaches RPC Files too. `origins` only adds to one app-wide allow-list for the RPC wire (the union of `start({ origins })` and every export), so no file narrows it.
- **Defaults.** `HEAD` runs `GET` and drops the body unless the file exports `HEAD`. `OPTIONS` answers 204 with `Allow` unless exported. An unsupported method is `MethodNotAllowed`, which unhandled answers 405 with `Allow` as in ADR 0039. No CORS headers are sent: the app sets them in `wrap` through `ResponseHeaders`.

## Consequences

- A Controller Method is not a `Handler`: it takes decoded input, not the `Request`, and reads raw request data with `yield* Request`. Hand-registered handlers keep the `Handler` shape and `callHandler`. `@sleekstack/testing` gains `callController(entry, request, { layer })`: `entry` is the Controller's generated entry (the annotations are erased at run time, so the Schemas and options come from the generated app module), and it resolves to the `Response` the HTTP face gives.
- Realworld's `rest.ts` becomes Controllers, and its `wrap` provides `ViewerLive(token)` and maps the tagged errors. A catch-all `[...rest].controller.ts` answers an unknown `/api/` path with JSON 404. A splat needs one segment or more (ADR 0050), so `/api` itself needs `index.controller.ts`.
- `ResponseStatus` joins `RequestServices`, so an `implement` method may use it. It has no effect on the `/_sleek/fn` wire.
- A plain TS annotation is as strict as its type (ADR 0051): `name: string` accepts the empty string. A constraint needs a referenced Schema.
- New `AnalyzeCode` values: `ControllerMethodShape` and `ControllerParamsMismatch`, each with its table row.
- The analyzer reads the annotation syntactically, because `Schema.Type<typeof X>` resolves to a structural type that no longer names `X`.

## Rejected

- **A `method({ params, success, error }, fn)` helper.** The Schemas would sit in a server-only file, and the browser client that ADR 0054 generates must import them. Stripping the file in the client build rests on import pruning, which ADR 0051 rejected.
- **A keyed `schema` export or a sibling Schema File paired by name,** with `status` as a field of it. It needs a second place to look and an annotation anyway to type the method.
- **A cast the author decodes in the body** (`yield* Body(S)`). A cast can lie, and the RPC wire needs a Schema value at run time, not a type.
- **A `status` option export, or a returned `Response` for the status.** A returned `Response` cannot cross the RPC wire (ADR 0054).
- **Controllers beside pages in `src/routes`.** The page scan takes every `.ts` file there, and `src` is the client graph.
- **Decorators and class controllers.** The repo is Effect functions and Layers; a class adds a second way to provide services.
- **A Controller that is also a Server Service by default.** Each method would have two faces with different auth (a token header against a cookie) and different error shapes. ADR 0054 makes the second face opt in.
