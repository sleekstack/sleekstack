<objective>
Implement `@sleekstack/core` from scratch: the `module()` function plus internal DFS circular-import detection, and the rewritten public type surface. This replaces the divergent prototype (`createService`, `layer`, `EffectLib`) entirely.

Purpose: `module()` is the pure-data foundation of the whole library — it carries a name, an array of Layers, imported Modules, and exported Tags, and it fails fast (synchronously, at call time) on a circular import graph with a readable cycle trace. It creates no Effect runtime (that is `@sleekstack/react`'s job per ADR 0001).
Output: `cycle.ts` (internal), `types.d.ts` (rewritten), `index.ts` (rewritten) — turning the CORE-01, CORE-02, CORE-04 tests from Plan 01-01 green.
</objective>

  <name>Task 1: Implement DFS circular-dependency detection in cycle.ts</name>
  <files>packages/core/src/cycle.ts</files>
  <behavior>
    - A linear import chain (A imports B imports C, no back-edge) does not throw
    - A direct cycle (A imports B, B imports A) throws synchronously
    - A transitive cycle (A imports B imports C imports A) throws synchronously
    - The thrown Error message contains the cycle as an arrow-joined trace starting and ending at the repeated module name, joined with ` -> `
    - A module graph with a shared diamond import (A imports B and C, both import D) does NOT throw — a re-visited-but-not-on-current-path node is not a cycle
  </behavior>
  <read_first>
    - .planning/phases/01-core-runtime/01-RESEARCH.md (Pattern 4: Circular Dependency Detection, lines 363-385; Code Examples "Circular Dependency Detection (Verified)", lines 529-549)
    - .planning/phases/01-core-runtime/01-PATTERNS.md (cycle.ts section, lines 111-137)
    - packages/core/src/__tests__/cycle.test.ts (the failing CORE-02 tests this must satisfy)
    - .planning/REQUIREMENTS.md (CORE-02 exact text)
  </read_first>
  <action>
    Create packages/core/src/cycle.ts exporting `detectCycles(mod)`. Accept a structural input typed as a minimal shape with a `name: string` and optional `imports` array of the same shape (do NOT depend on the full Module type to keep this file independent). Run a depth-first traversal using a `visiting` Set that tracks the names currently on the recursion stack and a `path` array. On encountering a name already in `visiting`, compute the cycle slice from the first occurrence of that name in `path` to the end, append the repeated name, join with ` -> `, and throw an Error whose message is `Circular module dependency detected: <trace>`. Add the name to `visiting` before recursing into each import and delete it after (so a diamond/shared import that is NOT on the current stack does not falsely trigger). Use the per-CORE-02 message format with the ` -> ` separator. Keep it O(V+E); the visiting-set bound guarantees termination so there is no stack-overflow DoS path (per 01-RESEARCH.md Security Domain).
  </action>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `module()` `name` field | mitigate | Validate `name` is a non-empty plain string at function entry; never use `name` as an object/property key without it being a plain string value — prevents prototype-pollution via crafted module names (01-RESEARCH.md Security Domain, V5). |
| T-02-02 | Denial of Service | cycle detection DFS | mitigate | DFS uses a `visiting` Set bounding traversal to O(V+E); the set guarantees termination, so a malformed/large import graph cannot cause infinite recursion or stack overflow (01-RESEARCH.md Security Domain). |
| T-02-03 | Information Disclosure | circular-dependency error message | mitigate | The error message names modules by their declared `name` identifier and the cycle trace only; it does not embed internal call stacks or runtime internals (01-RESEARCH.md Security Domain). |
| T-02-04 | Tampering | `imports` array elements | mitigate | Treat each import structurally (name + imports) for cycle detection; do not eval or invoke untrusted fields. |
</threat_model>
