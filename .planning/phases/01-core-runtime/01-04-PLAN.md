  <action>
    Extend LayerProvider so a nested provider inherits its parent's resolved context and child layers shadow parent layers, per 01-RESEARCH.md Pattern 2.

    Read the parent ProviderState via useContext(ProviderContext) (a nested provider has a non-null parent; a top-level provider has null). When a parent exists, the composed child layer must place the parent's context FIRST and the child's own layers LAST in Layer.mergeAll so the child overrides the parent for duplicate Tags (Pitfall 2: last-in-array wins; child-first ordering is the bug to avoid). Obtain the parent context by running Effect.context() on the parent runtime and wrapping it with Layer.succeedContext; because that extraction is async (parent builds lazily), have the nested provider suspend (throw the in-flight Promise) while building its layer, so the parent's <Suspense> boundary catches it (Open Question 1 recommendation; Assumptions A1/A4). The child's own layers are produced by the same assembleLayer flattening from Plan 01-03 (Module values flatten _layers + recursively-flattened imports — this is CORE-03's auto-pull). For a top-level provider (null parent) keep the Plan 01-03 single-scope behavior unchanged.

    Inner-before-outer finalization (REACT-02 ordering) is naturally satisfied because each provider's useEffect cleanup disposes its own runtime and React runs inner cleanups before outer cleanups; verify this holds in the test rather than adding manual ordering code. If parent-context plumbing requires a new field on ProviderState (e.g. exposing the parent runtime to the child), add it to context.ts; otherwise leave context.ts unchanged. Do NOT add an overrides prop — shadowing is via provide ordering only (ADR 0003).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| nested provider → parent runtime | The child provider reads/extracts the parent's resolved Effect context |
| playground consumer → library API | The demo app is an external consumer of @sleekstack/core + @sleekstack/react |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Reliability / DoS | nested-provider async parent-context extraction | mitigate | Extraction uses `await parentRuntime.runPromise(Effect.context())` and suspends the child while building; idempotent dispose + ref reset prevent leaks if the child unmounts mid-build (01-RESEARCH.md Pitfall 4, Assumptions A1/A4). |
| T-04-02 | Tampering | shadowing layer precedence | mitigate | Shadowing is purely positional in `Layer.mergeAll` (child layers last); no runtime privilege model — consistent with ADR 0003's single mechanism, removing a second override API as attack surface. |
| T-04-03 | Information Disclosure | playground error rendering | mitigate | The ErrorBoundary renders `error.message` only (no stack), consistent with the library's identifier-only error policy (01-RESEARCH.md Security Domain). |
</threat_model>
